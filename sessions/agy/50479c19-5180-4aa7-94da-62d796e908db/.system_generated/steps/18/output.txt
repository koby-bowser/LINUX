In NetBox, the `AUTHENTICATION_BACKENDS` setting is a Django configuration list that determines the order and methods used to authenticate users[1][2]. Because NetBox is built on Django, it utilizes Django's authentication system, where each backend in this list is checked sequentially until one succeeds[2][3].

### Common Configuration Patterns
*   **Default Behavior:** By default, NetBox uses a combination of local database authentication and remote user handling[1].
    ```python
    AUTHENTICATION_BACKENDS = [
        'netbox.authentication.RemoteUserBackend',
        'netbox.authentication.ObjectPermissionBackend',
    ]
    ```
*   **Integrating LDAP:** When adding LDAP support (typically via `django_auth_ldap`), the LDAP backend is usually prepended to the list to ensure it is checked before falling back to local credentials[4][3].
    ```python
    AUTHENTICATION_BACKENDS = [
        'django_auth_ldap.backend.LDAPBackend',
        'django.contrib.auth.backends.ModelBackend',
    ]
    ```
*   **Integrating SSO (OAuth/OIDC):** For Single Sign-On providers (like Keycloak, Azure AD, or GitHub), you typically add the specific backend from `social_core` or `drf_social_oauth2`[5][6][7].
    ```python
    AUTHENTICATION_BACKENDS = [
        'social_core.backends.azuread.AzureADOAuth2',
        'django.contrib.auth.backends.ModelBackend',
    ]
    ```

### Key Considerations
*   **Sequential Processing:** Django processes these backends in the order defined[3]. If you want to prioritize external authentication (like LDAP or SSO) while keeping local accounts as a fallback, ensure the external backend is listed before `django.contrib.auth.backends.ModelBackend`[3].
*   **Permissions:** Note that `netbox.authentication.ObjectPermissionBackend` is essential for NetBox’s internal permission system and is typically required even when using external authentication backends[1].
*   **Required User Accounts:** Regardless of the authentication backend used, a corresponding user record must generally exist in the NetBox database for the user to be granted access and permissions[8][2]. You can pre-provision these via the REST API or the built-in CSV import tool[8].
