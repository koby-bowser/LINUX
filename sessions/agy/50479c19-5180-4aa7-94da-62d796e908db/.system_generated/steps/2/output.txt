The search for "netbox multiple ldap domains django auth ldap" returned the following summary:
To configure multiple LDAP domains in NetBox (which utilizes `django-auth-ldap`), you must define multiple authentication backends, as the standard `django-auth-ldap` settings are prefixed with `AUTH_LDAP_` and are intended for a single configuration[1][2].

### Implementation Steps

#### 1. Create Custom Backend Subclasses
Since `django-auth-ldap` identifies its settings by a prefix, you can create a custom Python module (e.g., `custom_backends.py`) to define separate backend classes that point to different setting prefixes[1][2][3].

```python
# custom_backends.py
from django_auth_ldap.backend import LDAPBackend

class LDAPBackend1(LDAPBackend):
    settings_prefix = "AUTH_LDAP_1_"

class LDAPBackend2(LDAPBackend):
    settings_prefix = "AUTH_LDAP_2_"
```

#### 2. Update `configuration.py`
In your NetBox `configuration.py`, update the `AUTHENTICATION_BACKENDS` to include your new classes. Django will iterate through these backends until one successfully authenticates the user[1][2].

```python
# configuration.py
AUTHENTICATION_BACKENDS = (
    'path.to.custom_backends.LDAPBackend1',
    'path.to.custom_backends.LDAPBackend2',
    'django.contrib.auth.backends.ModelBackend', # Keep local auth as a fallback
)
```

#### 3. Define Settings for Each Domain
In your `ldap_config.py` (or directly in `configuration.py` if preferred), define the settings using the prefixes you assigned to the backend classes[1][2]:

```python
# LDAP Domain 1
AUTH_LDAP_1_SERVER_URI = "ldaps://ldap1.example.com"
AUTH_LDAP_1_USER_DN_TEMPLATE = "uid=%(user)s,ou=users,dc=domain1,dc=com"
# ... other AUTH_LDAP_1_* settings

# LDAP Domain 2
AUTH_LDAP_2_SERVER_URI = "ldaps://ldap2.example.com"
AUTH_LDAP_2_USER_DN_TEMPLATE = "uid=%(user)s,ou=users,dc=domain2,dc=com"
# ... other AUTH_LDAP_2_* settings
```

### Important Considerations
*   **Global Settings:** Note that `AUTH_LDAP_GLOBAL_OPTIONS` is global and ignores prefixes[1][2]. It is applied once when the LDAP module is loaded.
*   **Active Directory Forest:** If you are using Active Directory and simply need to reach multiple domains within the same forest, you may not need separate backends. You can often configure `AUTH_LDAP_SERVER_URI` to point to the **Global Catalog** (port 3268 or 3269 for LDAPS), which allows searching across the entire forest with a single configuration[4][5].
*   **Local Fallback:** Always ensure `django.contrib.auth.backends.ModelBackend` remains in your `AUTHENTICATION_BACKENDS` list so that local superusers can still log in if the LDAP servers become unreachable[6][7].
