In NetBox, the `AUTHENTICATION_BACKENDS` setting is defined in `netbox/settings.py` to determine which authentication mechanisms the application uses and in what order[1][2].

### Default Configuration
By default, NetBox typically includes its own remote backend and the object permission backend[3][4]:

```python
AUTHENTICATION_BACKENDS = [
    'netbox.authentication.RemoteUserBackend',
    'netbox.authentication.ObjectPermissionBackend',
]
```

### Customizing Authentication
When you need to implement custom authentication (such as LDAP, OAuth, or SAML), you generally modify this setting in your `configuration.py` file rather than editing `settings.py` directly[1][5].

*   **LDAP:** If you enable LDAP, you often need to ensure the LDAP backend is included in the list[6][7].
    ```python
    AUTHENTICATION_BACKENDS = [
        'netbox.authentication.LDAPBackend',
        'django.contrib.auth.backends.ModelBackend',
    ]
    ```
*   **Order Matters:** The order of backends is important[2]. Django iterates through them until one successfully authenticates the user[8]. If you are adding a new backend (like for SSO or TACACS+), you must typically include the default `ModelBackend` (for local database users) if you wish to retain the ability to log in with local accounts[2][9][10].

### Important Notes
*   **Do Not Modify `settings.py` Directly:** It is strongly recommended to define `AUTHENTICATION_BACKENDS` in your `configuration.py` file[1][5]. NetBox is designed to pick up these settings from `configuration.py`, and modifying the core `settings.py` can cause issues during upgrades or with containerized deployments[1].
*   **Remote Auth:** Many authentication methods rely on the `REMOTE_AUTH_ENABLED` setting being set to `True` in `configuration.py` alongside the appropriate `REMOTE_AUTH_BACKEND`[8][11].
